# 모니터링 대시보드

주소: http://127.0.0.1:15273

## 화면과 사용법

- **서비스 개요**: 선택 기간의 총 요청, HTTP 5xx 오류율, 평균·P95 응답 시간과 시계열 차트. 마우스를 올리거나 차트에 키보드 초점을 두고 좌우 화살표로 구간 값을 확인합니다.
- **엔드포인트**: 요청량 상위 50개 API를 P95·요청량·오류율로 정렬하고 경로로 검색합니다. 행을 선택하면 해당 API의 요청 탐색 화면으로 이동합니다.
- **요청 탐색**: 선택 기간의 최신 100건에서 경로·이벤트 ID 검색, 5xx·4xx·느린 요청 필터, 최신순·느린 순 정렬을 지원합니다. 상세 창에서 상태 코드·측정 시간·배포 버전·이벤트 ID를 확인합니다. 전체 이력을 검색하는 기능은 아닙니다.
- **알림 센터**: 오류율·응답 시간 규칙, 반복 억제 남은 시간, 이메일 상태와 최근 50건 타임라인을 표시합니다. 알림 타임라인은 조회 기간과 별개입니다.
- **인프라 상태**: MySQL·Redis·Kafka 연결과 서비스별 최근 수신을 확인합니다.

5분·15분·1시간 기간 선택, 서비스·환경 선택, 15초 자동 갱신, 일시정지와 수동 갱신을 지원합니다. 갱신을 멈추는 동작은 브라우저 조회에만 적용되며 서버의 수집·알림은 계속됩니다.

## 수치의 의미

차트와 상단 지표는 MySQL에 저장된 **선택 기간의 요청**을 집계합니다. 상단 상태 배지와 알림 규칙의 현재 값은 Redis의 **최근 5분**을 사용합니다. 기간 선택으로 알림 판단 조건이 바뀌지 않습니다.

- 요청 처리량: 구간 요청 수 ÷ 구간 초. 5분 조회는 10초, 15분은 30초, 1시간은 120초 구간입니다.
- 오류율: 5xx 요청 수 ÷ 전체 요청 수 × 100. 4xx는 분자에 포함하지 않습니다.
- P95: 요청을 처리 시간순으로 정렬한 뒤 `ceil(요청 수 × 0.95)`번째 값을 선택합니다. 기간 전체 P95를 구간 P95의 평균으로 대체하지 않습니다.
- 빈 구간: 요청 수는 0, 오류율·평균·P95는 `null`입니다. 지연 차트에서 빈 구간을 0ms로 그리거나 연결하지 않습니다.
- 시각: 화면은 Asia/Seoul, 저장·조회 경계는 UTC입니다. 조회 범위는 `[from, asOf)`입니다.
- 요청 없음은 서비스 정상이나 가용성 100%를 뜻하지 않습니다. 상단에서 별도로 표시합니다.

API: `GET /api/v1/services/{serviceKey}/analytics?environment=development&minutes=15`

`minutes`는 5·15·60만 허용합니다. 시간 인덱스가 적용된 범위를 SQL로 집계하며, MySQL 창 함수를 이용해 기간·구간·API별 P95를 계산합니다. 한 응답의 여러 조회는 읽기 전용 repeatable-read 트랜잭션에서 일관된 스냅샷을 사용합니다. 응답 크기는 차트 30개 구간, API 최대 50개, 요청 최대 100건으로 제한됩니다. 장기간 통계나 대규모 트래픽에는 사전 집계 테이블이 추가로 필요합니다.

## 검증

```bash
python3 scripts/analytics-e2e.py
(cd backend && ./gradlew test bootJar)
(cd frontend && npm run build)
```

`analytics-e2e.py`는 고유한 서비스의 이력 행만 MySQL에 생성하고 종료 시 제거합니다. Kafka 이벤트나 이메일을 발생시키지 않습니다. 실제 MySQL에서 기간·환경 격리, 평균/P95, 구간별 합계, API별 집계, 빈 데이터, 잘못된 조회 조건을 검증합니다.

2026-10-14: 모니터링 단위 테스트 28개, MySQL 분석 API 통합 검증, Vue 타입 검사·빌드 통과. 브라우저에서 기간 변경, API 선택→요청 탐색, 느린 요청·5xx 필터, 요청 상세 창과 실제 이메일 발송 이력을 확인했습니다.
